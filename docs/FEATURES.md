# imyemail 功能说明

本文以 `v1.3.27` 为基准，整理前台、管理后台、标准邮件协议、开放接口和运维能力。版本级变化见 [更新日志](../CHANGELOG.md)，部署边界见 [架构说明](ARCHITECTURE.md)，改动完成标准见 [开发与发布规范](DEVELOPMENT.md)。

## 前台账号与 Webmail

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 登录 | 登录页 | 支持登录名或已绑定的完整邮箱地址；邮箱地址登录会进入对应账号 |
| 多邮箱 | 邮箱页侧栏 | 切换当前邮箱；退出登录和切换账号入口在账号菜单中 |
| 邮件阅读 | 收件箱及文件夹 | 会话阅读、已读/未读、星标、标签、移动、删除、稍后提醒和附件下载 |
| 写信 | 写信窗口 | 新邮件、回复、转发、草稿、定时发送、单附件大小校验和发送状态反馈 |
| 邮件整理 | 邮箱页 | 全文搜索、自定义文件夹、标签、导入、导出及批量操作 |
| 我的图库 | 写信窗口 | 直连用户配置的 `tu.my` 或兼容 HTTPS 上传接口；令牌仅保存在当前浏览器 |
| 外部邮箱 | 账号设置 → 邮件 | 添加外部 IMAP 账号，测试连接、选择同步方式并查看同步结果 |
| 邮箱申请 | 账号设置 → 邮件 | 在管理员允许的域名和额度内自助申请邮箱 |

## 个人设置与自动化

“账号设置”按账号、邮件、通知与客户端、安全四组整理：

- 账号：个人资料、登录密码、API Token 及其 scope。
- 邮件：联系人、签名、默认签名、收件规则、拦截发件人、转发、邮箱申请、邮件统计和清理。
- 通知与客户端：查看最近 90 天的 SMTP、IMAP、POP3 登录结果，支持选择和批量删除。
- 安全：标准 TOTP 双因素认证、一次性恢复码，以及启用 2FA 后按邮箱生成的第三方客户端应用密码。

“通知与客户端”以桌面表格和移动卡片展示 IMAP 993、POP3 995、SMTP 465 与 Submission 587；服务器、端口和完整邮箱用户名均有独立复制按钮。用户可在“反馈”提交工单、接收管理员回复、继续对话、关闭或经二次确认删除。工单按账号隔离且仅显示纯文本，关闭后双方不能回复。

收件规则支持按发件人、收件人、主题等条件组合匹配，并执行移动、归档、回收、星标、标记已读、添加标签或转发。规则可以调整顺序，也可以手动应用到已有邮件。

## 管理后台

| 菜单 | 主要能力 |
| --- | --- |
| 数据总览 | 账号、邮箱、域名、邮件、附件、发送队列和客户端连接统计；7 天收发趋势、队列状态、安全状态和邮箱存储排行 |
| 账号管理 | 创建、编辑、停用和删除账号；修改角色、邮箱额度、权限组，重置密码或 2FA |
| 权限配额 | 按权限组控制前台功能、后台菜单、邮箱数量、发信频率和附件上限 |
| 域名管理 | 域名状态、DKIM、逐条复制 DNS 记录、DNS 检测和邮件健康评分 |
| 邮箱管理 | 创建、分配、停用和删除邮箱；设置容量及每邮箱附件上限 |
| 邮件转发 | 创建、启停和删除别名或域名内转发规则 |
| 全部邮件 | 按邮箱、文件夹和关键词筛选，查看正文与附件，批量已读、星标、移动或删除 |
| 发送队列 | 按邮箱、状态、发件人、收件人、关键词和时间筛选，查看投递审计并批量重试、取消或删除 |
| 反馈工单 | 按状态查看用户反馈和双向对话，回复、标记处理中、关闭或经二次确认删除；查看与管理权限分离 |
| 系统设置 | 站点名称与浏览器标题、简体中文/繁體中文/English 默认语言、前后台界面模板、SMTP、SSL 证书、存储、邮件、外部 IMAP、安全、邮件模板、全域公告和关于信息 |

系统设置中的全域公告支持普通、重要、紧急三个级别；所有已登录用户会在邮箱顶部看到当前公告。公告按纯文本渲染，不执行 HTML。

“系统设置 → 界面模板”提供五套全站模板：`imyemaildefault` 保持原有经典界面，`imyemailcloud` 使用靛蓝强调色与悬浮层次，`imyemail-cloud-sy` 参考 SoybeanAdmin 的紫蓝 token 和分层内容区，`imyemail-vbena` 参考 Vben Admin 5.7 的蓝色品牌 token、224px 侧栏、50px 顶栏、圆角导航和模块化卡片，`imyemail-cloud-byte` 参考 Arco Design 2.66.16 的品牌蓝、灰阶层次、240px 基准侧栏、60px 顶栏和轻量表单卡片。Vben 登录页与 Arco 登录/注册页使用邮箱品牌视觉，两者的 Webmail 侧栏显示公开站点名称并回退为 `imyemail`。四套扩展模板在桌面和超宽屏使用全部可用内容宽度，并自适应扩展邮件导航与列表；移动端继续使用单栏布局。管理员保存后，登录、注册、Webmail、个人中心和管理后台统一切换；模板说明支持简体中文、繁体中文和英文，模板名称由后端固定白名单校验并通过公开设置下发。设计来源、响应式契约和安全边界见 [界面模板说明](UI-TEMPLATES.md)。

“系统设置 → 基础 → 默认语言”控制新访客和未保存个人语言偏好的用户界面，支持 `zh-CN`（简体中文）、`zh-TW`（繁體中文）和 `en`（English）。该值保存在 `system_settings`，由公开设置接口下发；后端固定白名单拒绝其他值。用户可从登录、注册、Webmail 或个人中心选择语言，选择结果保存在浏览器本地并优先于管理员默认值。textarea 与富文本编辑器会翻译 placeholder、标题和无障碍标签，但用户输入的邮件正文、签名、自动回复及反馈内容不会进入界面翻译流程。

## 在线更新与回滚

超级管理员点击后台侧栏版本号，可执行以下操作：

1. 检查当前版本、最新 GitHub Release 和更新日志。
2. 点击“立即更新”；API 先创建 SQLite 在线备份并返回 `202 Accepted`。
3. 内部 Operator 保存当前镜像与 Compose 回滚点，再异步调用 Watchtower 更新应用。
4. 更新后可查看上一版本和回滚点时间，并经二次确认回滚。
5. 不再需要回滚点时，可二次确认删除保存的旧镜像与 Compose 回滚文件。

回滚只切换镜像和 Compose，不会回退数据库。执行回滚前会再次备份 SQLite。删除回滚点不会删除当前镜像、SQLite、Maildir、附件、证书或 DKIM 数据；若旧镜像仍被容器使用，Docker 会拒绝删除并保留回滚元数据。Operator 和 Watchtower 都只在 Compose 内部网络监听，使用随机令牌鉴权，不发布宿主机端口。

从 `v1.3.11` 或更早版本升级时，应先在服务器运行一次：

```bash
sudo imyemail update
```

这样 Manager 才会刷新 Compose、启动 Operator，并保留升级前镜像作为回滚点。

## SMTP、IMAP 与 POP3

| 用途 | 协议和端口 | 客户端用户名 | 密码 |
| --- | --- | --- | --- |
| 收件 | IMAP SSL `993` | 完整邮箱地址 | 邮箱密码；启用 2FA 后使用该邮箱的应用密码 |
| 收件 | POP3 SSL `995` | 完整邮箱地址 | 邮箱密码；启用 2FA 后使用该邮箱的应用密码 |
| 发件 | SMTP SSL `465` | 完整邮箱地址 | 邮箱密码；启用 2FA 后使用该邮箱的应用密码 |
| 发件 | SMTP STARTTLS `587` | 完整邮箱地址 | 邮箱密码；启用 2FA 后使用该邮箱的应用密码 |

SMTP Submission 支持 `AUTH PLAIN` 和 `AUTH LOGIN`。Dovecot 负责 IMAP/POP3 验证，Go API 负责 SMTP Submission；三种协议的成功或失败鉴权都会进入当前用户可见的客户端连接记录。
前台“账号设置 → 通知与客户端”在桌面端使用表格、窄屏使用卡片，服务器、端口和用户名均有独立复制按钮；密码区只根据 2FA 状态提示使用邮箱密码或应用密码。用户配额与后台配额设置中的 IMAP/POP3 频率均以每分钟“请求数”表示。

## 邮件兼容与安全

- MIME 正文会先解码传输编码，再按声明的 charset 转成 UTF-8；兼容 GB18030、GBK、GB2312 等常见中文邮件。
- Postfix、Dovecot、Rspamd 和 DKIM 共同完成收信、投递、垃圾检查和签名。
- ACME 支持 Let's Encrypt、ZeroSSL 和 Google Trust Services；签发成功后自动重载 Web、SMTP、IMAP 和 POP3 证书。
- TOTP 使用标准 `otpauth://` URI，支持常见验证器扫码、有限时间漂移和一次性恢复码。
- 开放 API 使用带 scope 的 Token；Webhook 使用 HMAC-SHA256 签名；外部网络请求默认执行 SSRF 防护。
- Session Cookie、数据库、证书私钥、DKIM 私钥和更新令牌均有独立安全边界。

## 开放 API 与 Webhook

稳定集成入口为 `/api/open/v1`，支持域名、DNS、邮箱、别名、邮件发送、发送状态、事件、重试、取消、收件查询和附件下载。浏览器会话接口不属于开放 API 稳定契约。

系统同时支持：

- 外部投递平台向 `/api/open/v1/delivery-events` 回传最终投递状态。
- imyemail 将发送队列和投递变化主动推送到配置的状态 Webhook。
- HMAC 时间戳签名、幂等事件和失败退避重试。

完整请求格式见 [API 文档](API.md) 和 [OpenAPI 3.1 契约](openapi.json)。

## 数据、备份与迁移

- SQLite 保存账号、设置、索引和队列；Maildir 保存邮件原文，附件和 DKIM 私钥分别持久化。
- `imyemail backup` 创建 SQLite 一致性在线备份，但不包含 Maildir、附件、DKIM 和 `.env`。
- 完整灾难恢复必须成套保存 `.env`、`data`、`mail` 和 `dkim`。
- Manager 支持安装、更新、备份、状态、诊断、日志、启停、重启、回滚和安全卸载；安装完成时汇总访问地址、初始管理员用户名、密码安全获取方式和数据目录，不输出明文密码。

备份、恢复和迁移命令见 [安装与运维](OPERATIONS.md)。

## 部署支持范围

- 默认生产路径：All-in-one Docker 镜像与 Rust Manager。
- 支持主机：Debian/Ubuntu Linux，`amd64` 和 `arm64`。
- Split stack 用于开发、调试和预发布验证，不是默认生产部署。
- CSS/JavaScript 正式版本使用固定版本的 jsDelivr 地址，加载失败时回退到容器本地静态资源。

## AI 邮件助手

- 管理员在「系统设置 → AI 邮件助手」启用服务，选择主流服务商预设或自定义第三方接入，填写协议、公网 HTTPS Base URL、API KEY 和模型。支持 OpenAI Chat/Responses、Claude Messages、Gemini GenerateContent，默认关闭。支持获取模型、下拉选择或手动输入；可直接测试当前未保存配置，并显示脱敏诊断；预设和兼容边界见 [服务商接入](AI-PROVIDERS.md)。
- 写信工具栏点击「AI 写邮件」，填写目的、语气和要点；生成结果可编辑、重新生成，确认后追加到现有正文，支持编辑器撤销。
- 阅读本人本地或外部 IMAP 邮件时，可点击「AI 总结」或「AI 回复」。回复结果采用后打开原有写信窗口，保留原文引用，由用户检查并发送。
- 输出语言跟随界面语言（简体中文、繁體中文、English）。五套模板共用组件，弹窗使用可滚动正文与固定操作区，适应移动端、宽屏和浅深色主题。
- 界面在生成前说明数据发送范围；KEY 不返回浏览器，附件和收件人列表不发送。正文中本来包含的地址、签名或引用仍属于正文，可能发给服务商。
- 每账号每分钟最多 10 次，每个 Go API 进程最多并发 4 次。超长阅读内容仅处理前 20000 字并提示；超过 20000 字的写信草稿要求缩短；结果可能不准确，不自动发送邮件。

验证范围：Go 全量与 AI 竞态测试覆盖四种协议、本地/外部 IMAP 归属、权限、CSRF、取消、KEY 脱敏、SSRF、限流及异常响应。Web 类型、构建、组件/模板/三语/编辑器检查通过；Rust API 与 Manager 格式、Clippy、测试及修复后的依赖审计通过。Chrome/Firefox 验证生成、追加、取消、总结、回复、配置保存、服务异常、停用和三语内容保护；生成弹窗及服务商配置分别覆盖五模板 × 四宽度 × 浅深色 × 两引擎。容器与发布验证状态见 [验证记录](AI-VERIFICATION.md)。未提供真实 AI KEY，真实服务商联调尚未执行，预设数量不代表已完成逐家付费验收。
